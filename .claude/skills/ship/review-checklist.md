# Pousse review checklist

Apply every rule to the branch diff; each one ends "holds" or "fixed".

## Both apps

- **Language**: identifiers, files, routes, columns, enum values, errors,
  logs, comments, docs in English. French only in mobile UI copy (labels,
  accessibility labels, copy derived from error codes, demo seeds), ADRs and
  database row content.
- **Scope**: every changed file serves an acceptance criterion; the diff stays
  inside the ticket's file list or the plan says why.
- **Dependencies**: no new package, or the plan justified it.
- **ADRs**: none edited; a changed decision has a new ADR superseding the old.
- **Strict TypeScript**: no `any`, `import type` for type-only imports,
  kebab-case files, one entity / use case / component / route per file.

## `apps/mobile`

- **Hexagon**: `domain` imports nothing outside itself; use cases take ports
  through the constructor, expose one `execute()`, never import React; no use
  case receives `IdGenerator` or `Clock`; a module reaches another only
  through its `index.ts` barrel and never touches its repository.
- **Thin UI**: screens hold no business rule (validation, streaks, seeding)
  and reach the core only through `useServices()`; route files only re-export
  a screen.
- **Errors**: every async call a screen makes has its failure handled and
  shown as French copy through a formatter, never `error.message`.
- **Cocon design system**: colors and fonts from `src/shared/ui/theme/`, flat
  editorial layout, at most one filled accent surface per screen, existing
  shared components reused.
- **Accessibility**: every `Pressable` has a role and a French label (plus a
  hint when the outcome is not obvious); selections use radiogroup/radio with
  `selected`; titles are headers; every `TextInput` has a label.

## `apps/api`

- **Validation**: every route declares Zod input and response schemas; no
  field reaches the client outside its response schema.
- **Modules**: a route calls a service, never a repository; a service calls
  another module's service, never its repository.
- **Schema**: Drizzle is the only source of the physical schema; constraints
  the database can express are declared there; the migration is generated by
  drizzle-kit, not written by hand.
- **Auth**: BetterAuth defaults kept (no JWT, no refresh token); client IP from
  `X-Client-IP`.
- **Tests**: new routes and constraints have integration tests on the real
  PostgreSQL container, no mocked data access.
